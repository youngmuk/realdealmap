# realdealmap-data

RealDealMap의 데이터 파이프라인과 갱신 트리거. 국토교통부 실거래가 Open API에서 자료를 수집해
정규화·좌표 결합 후 Cloudflare R2에 불변 청크로 배포한다.

설계 근거는 `Doc/기술검토서.html`(rev.2), 작업 단위는 `Doc/jobs/작업계획.html`을 참조한다.

## 구성

| 경로 | 역할 |
| --- | --- |
| `packages/shared` | 시군구 카탈로그, 공통 타입 |
| `packages/ingest` | 국토부 수집 · 정규화 · 청크 생성 · R2 업로드 |
| `packages/geocode` | 주소→좌표 사전 구축 |
| `packages/worker` | 갱신 트리거 Worker + 지역 Durable Object |
| `.github/workflows` | 수집 워크플로 (dispatch · schedule) |

## 시군구 카탈로그

실거래가 API는 시군구 5자리 코드(`LAWD_CD`)와 계약년월(`DEAL_YMD`)로 조회한다.
그 코드 목록을 행정표준코드관리시스템의 법정동코드 전체자료에서 생성한다.

```bash
npm run regions        # 내려받기 + 생성
```

생성물:

- `packages/shared/data/regions.json` — 시군구 레벨 269건, 그중 **조회 대상 256건**
- `packages/shared/data/legacy-codes.json` — 폐지 코드 → 현행 코드 매핑 92건

원본(`packages/shared/raw/`)은 커밋하지 않는다. 생성물만 커밋한다.

### 조회 대상이 256건인 이유

시군구 레벨 항목은 269건이지만, 일반구를 둔 시 13곳(수원·성남·안양·부천·안산·고양·용인·화성·
청주·천안·포항·창원·전주)은 그 자체로도 코드를 가진다. 하위 구와 중복 조회가 되므로
`queryable: false`로 표시해 조회 대상에서 제외한다.

### 주의: 행정구역 개편이 진행 중이다

- **광주광역시(29)와 전라남도(46)가 폐지되고 전남광주통합특별시(12)로 통합**되었다.
- 부천시(2024)·화성시(2025)에 일반구가 신설되었다.
- 강원도(42)→강원특별자치도(51), 전라북도(45)→전북특별자치도(52) 코드도 바뀌었다.

**국토부 실거래가 API가 과거 계약월에 대해 신·구 코드 중 무엇을 받는지는 확인되지 않았다.**
작업계획 T1.1에서 실호출로 검증한 뒤 조회 코드 결정 로직을 확정한다. 그 전까지
`legacy-codes.json`을 폴백 후보로 보존한다.

## 보안

서비스키·R2 자격증명은 **GitHub Secrets에만** 둔다. 이 저장소는 public이다.

- 워크플로 로그에 요청 URL 전체를 출력하지 않는다(`serviceKey`가 쿼리스트링에 들어간다).
- R2 토큰은 대상 버킷 하나로 범위를 제한하고 Object Read and Write만 부여한다.
- 카카오 REST 키는 **헤더로만** 나간다. URL 쿼리에 실으면 로그·프록시에 그대로 남는다.

필요한 Secrets:

| 이름 | 쓰는 곳 |
| --- | --- |
| `DATA_GO_KR_SERVICE_KEY` | 국토부 실거래가 호출 |
| `R2_ACCOUNT_ID` · `R2_ACCESS_KEY_ID` · `R2_SECRET_ACCESS_KEY` · `R2_BUCKET` | R2 업로드 |
| `CALLBACK_SECRET` | Worker 완료 알림 |

## 워크플로

| 이름 | 언제 도는가 | 하는 일 |
| --- | --- | --- |
| `refresh-region` | 앱 요청(Worker) · 수동 | 한 시군구의 최근 N개월을 수집해 배포한다 |
| `backfill` | 6시간마다 · 수동 | 아직 12개월이 없는 지역을 예산만큼 채운다 |
| `geocode-queue` | 매일 · 수동 | 주소를 좌표로 바꿔 사전을 채운다 |
| `metrics` | 매일 · 수동 | 운영 지표를 잡 요약과 아티팩트로 남긴다 |
| `backend-ci` · `app-ci` | 푸시·PR | 타입·린트·테스트 |

### 적재는 진행 상태를 따로 두지 않는다

`backfill`은 매 실행마다 R2에 "아직 12개월이 없는 지역"을 물어보고 앞에서부터
예산만큼만 처리한다. 어디까지 했는지를 파일이나 커밋으로 들고 있으면 적재가
중간에 끊겼을 때 그것과 실제 R2가 어긋나고, 그때부터는 무엇을 믿을지 알 수 없다.
매번 물어보면 몇 번을 끊고 다시 시작해도 같은 답이 나온다.

좌표는 여기서 만들지 않는다(`--geocode=0`). 국토부는 API마다 일 10,000건이라
전국 12개월이 하루에 들어가지만, 카카오는 계정 전체로 일 100,000건이고 전국
고유 주소는 그보다 훨씬 많다. 한 워크플로에 묶으면 느린 쪽이 빠른 쪽을 붙잡는다.
좌표가 없는 거래도 목록과 상세에는 그대로 나온다.

### 매니페스트는 이번에 안 만든 달을 이어받는다

매니페스트는 그 지역에서 살아 있는 파일의 **전체 목록**이다. 이번에 만든 것만
담으면 최근 3개월 갱신 한 번이 12개월 적재를 3개월로 줄인다. 실제로는 줄어들기
전에 건수 게이트가 보류를 걸어서, 12개월을 채운 지역은 매 시간 갱신이 보류로
끝난다.

이어받기의 기준은 **이번에 시도한 달**이지 만들어진 달이 아니다. 만들어진 달을
기준으로 삼으면 원천이 조용히 0건을 준 달(R-14)이 "안 만든 달"로 보여 이전
것으로 메워지고, 건수가 그대로라 게이트도 통과한다. 실종이 완벽히 감춰진다.

### 한 유형의 쿼터가 바닥나도 나머지는 배포한다

국토부 쿼터는 **API마다 따로** 하루 10,000회다. 전국 12개월 적재에서 토지 매매
하나가 먼저 바닥났는데, 그때는 그것이 지역 전체를 실패시켰다 — 나머지 여덟 유형을
멀쩡히 받아 둔 지역 174곳이 아무것도 배포하지 못했고, 받아 둔 것을 버리고 내일 다시
받느라 쿼터를 또 썼다.

지금은 그 유형만 접고 나머지를 계속한다. 남은 달도 시도하지 않는다(이미 바닥난 것을
다시 물어봐야 답은 같다). 손도 못 댄 (유형 · 월) 조합은 이전 매니페스트에서
이어받는다 — 안 그러면 그 유형이 사라진 것으로 보여 게이트가 지역을 보류한다.

**"손도 못 댐"과 "시도했는데 0건"을 가르는 것이 핵심이다.** 뒤엣것은 원천이 조용히
지운 경우(R-14)라 반드시 게이트에 걸려야 하고, 그 판정은 그대로 남아 있다.

### 좌표는 사전이 채워진 뒤 **다시 구워야** 붙는다

적재는 좌표 없이 12개월을 굽는다(`--geocode=0`). 카카오는 느리고 계정 전체가 하루
10만이라, 국토부 수집을 거기에 묶으면 둘 다 못 끝낸다. 그 뒤 `geocode-queue`가
사전을 채운다.

여기서 끝내면 지도는 그대로다. **매 시간 갱신은 최근 3개월만 다시 굽기 때문에**
나머지 아홉 달은 사전이 채워진 뒤에도 좌표 없는 청크로 남는다 — 목록에는 나오는데
지도에는 한 점도 안 찍힌다. `rebake-region.mjs`가 그 아홉 달을 이어 굽고,
`geocode-queue`가 지역마다 좌표를 채운 직후에 부른다.

**원천을 부르지 않는다.** 청크 레코드가 원본 항목(`raw`)을 그대로 들고 있어 거기서
다시 정규화한다. 붙일 좌표가 없으면 아무것도 올리지 않는다 — 같은 내용을 다시
올리면 `refreshedAt`만 바뀌어 앱이 108개 청크를 통째로 다시 받는다.

고유 주소는 거래 건수보다 훨씬 적다(울산 중구 실측: 6,833건에 653개). 사전은
빠르게 수렴한다.

## 앱 출시 빌드

```bash
app/tool/build-release.sh              # 스토어용 .aab
app/tool/build-release.sh apk          # 기기 확인용 .apk
```

**이 스크립트를 거치지 않은 산출물은 올리지 않는다.** `flutter build`에
`--dart-define`을 빠뜨려도 빌드는 성공하고 앱도 실행된다. 지도는 OSM 폴백으로
그려지고 데이터만 비어서, 화면만 봐서는 "아직 안 받았나 보다"와 구별되지 않는다.
OSM 이용정책은 앱 트래픽을 허용하지 않으므로 그대로 출시되면 규정 문제가 된다.

앱에도 같은 판정을 넣어 뒀다. 값이 빠진 빌드는 상태바에 **출시 불가**를 사유마다
한 줄씩 띄운다 — 스크립트는 우회할 수 있어도 첫 화면은 우회할 수 없다.

서명은 `app/android/key.properties`가 있으면 그것을 쓰고, 없으면 디버그 키로
서명한다(저장소를 받은 사람도 동작은 확인할 수 있어야 한다). 디버그 키로 서명된
것은 Play에 올릴 수 없다. 키스토어와 비밀번호는 저장소에 두지 않는다.

## 손으로 돌리는 것

스크립트는 `dist`를 import한다. `npm run` 경로는 앞에 `tsc --build`가 붙어 있어
갓 고친 코드가 반영되지만, `node packages/…`로 **직접 부르면 옛 `dist`가 돈다.**
고친 것이 안 먹는 것처럼 보이면 여기를 먼저 의심한다. 워크플로는 전부
`npm run typecheck`(= `tsc --build`)를 먼저 돌린다.

```bash
npm run verify                                    # 타입·린트·커버리지
node packages/ingest/scripts/backfill-plan.mjs --months=12 --limit=5
node packages/ingest/scripts/report-metrics.mjs --months=12
scripts/check-secrets.sh <APK 경로>               # 출시 전 (G6)
```
